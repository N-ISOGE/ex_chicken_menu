소유권
=====

개요
---

- 러스트의 가장 유니크한 특성
- 목적 : 가비지 콜렉터를 대신한 메모리 안정성 보장
- 관련 개념 : 빌림, 슬라이스, 러스트에서 데이터를 메모리에 저장하는 방식

소유권이란?
--------

- 러스트의 핵심

### 러스트의 메모리 관리법

- 다른 메모리 관리 예시 : 가비지 콜렉션; 명시적으로 할당, 해제; 생성자, 소멸자
- 러스트는 컴파일 타임에 컴파일러가 소유권 시스템을 이용해 확인
    - 런타임이 아닌 컴파일 타입 확인

소유권 규칙
---------

### 개요

1. 러스트의 각각의 값은 해당값의 오너라고 불리는 변수를 갖고 있다
2. 언제나 하나의 오너만 존재할 수 있다.
3. 오너가 스코프에서 벗어나면 그 값은 없어진다.

임시로 사용하는 변수들
------------------
### 스택에 저장하는 데이터, 스코프 기반

- 스코프 안에서 유효한 변수 -> 스택에 저장


### 힙에 저장하는 데이터, String 타입 예시

소유권 예시용  
힙에 저장된 데이터가 어떻게 생성, 제거되는지 봄

스트링 리터럴은 하드코딩되어 이미 불변값으로 할당됨

- 스트링 리터럴에서 값을 받는것
    - String::from(리터럴)

### 메모리와 할당

- 프로그램이 실행 중에 `크기가 다양한 자료`를 저장하는 경우가 생김
  - 이 때 `힙`에 할당, 저장하게 됨

- 이 메모리를 어떻게 반납하나?
    - 다른 방법으로 가비지 콜렉터가 사용하지 않는 메모리를 찾아서 반환함
    - 가비지 콜렉터가 없으니 프로그래머가 반납할 책임을 가짐
    - `할당 한번에 반납 한번을 정확히 하는 법`?


- 스코프를 벗어나면 기본적으로 언어에서 `drop 함수`를 호출해서  
  개발자가 메모리 반환하는 코드를 실행하게 할 수 있다
    - 소멸자 아님?
    - 수명주기가 끝나는 시점에 자원을 해제하는 패턴

### 변수와 데이터 간 상호작용 방법들

- 이동  
  단순 대입은 주소값만 복사, 얇은 복사 수준이 아닌 이동이라고 부름  
  `출발지인 변수는 유효하지 않게 됨`

- 클론  
  깊은 복사를 하려면 `clone 메소드`를 사용함  
  - 지시자 역할, 생각보다 많은 비용이 드는 동작을 의식할 수 있게 해줌

- 복사
    1. 스택에 저장할 수 있는 타입에는 `Copy trait` 이라는 어노테이션을 가짐
    2. 이 트레잇은 대입 후 이전 변수 사용가능, Drop 특성을 가지면 Copy 특성을 못 가짐
    3. __가질 수 있는 것 예시__
        - 정수형, bool, 부동 소수점 타입, Copy 특성 가진 타입으로 구성된 튜플

### 소유권과 함수

- 함수에게 값을 넘기는 동작과 값을 변수에 대입하는 동작 유사함  
  함수 내 스코프로 들어가면 이동한 것으로 취급함

- 함수가 값을 반환하는 것도 소유권을 이동시킴

### 값만 보여주는 것은 없나?
- 레퍼런스, 참조자라는 것이 존재
